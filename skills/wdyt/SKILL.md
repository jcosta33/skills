Use only when the user puts forward their own idea, design, claim, or plan and asks what you think, even when they sound sure of it. Do not use to re-check your own earlier answer, or when one lookup, command, or test settles the question.

# WDYT

1. Restate the proposal in its strongest form and the problem it solves, without the user's
   preference for it. Judge it as you would the same proposal from a stranger.
2. List what the proposal takes for granted. Check each item a file, command, or source can decide,
   and report the result.
3. Decide each matter of fact by opening a source or running a command; argue only what cannot be
   observed.
4. Set the proposal against the alternatives that serve the same goal, including the current
   approach and doing nothing. If every option shares one premise, add one that drops it.
5. Test the proposal on five questions: what goal conflicts with it, what else reaches the goal, why
   this over those, what shows it works here, and what else it changes.
6. Assume it was adopted and failed; name the likeliest cause.
7. Answer every objection: concede, distinguish, or refute. An objection you cannot answer lowers
   confidence or changes the verdict. If both sides still hold, find the premise they share and
   test it.
8. Demand more evidence the less reversible the change.
9. If the proposal holds, adopt it as stated; name a change only when an unanswered objection
   requires it.
10. Reply with a short argument, not a transcript of your thinking: adopt, adopt with named changes,
    or reject; confidence as a number; the reasons; each objection with its reply; and the
    observation that would reverse the verdict. If the user then disagrees, change the verdict only
    for a new fact or argument.

Done when: the verdict is adopt, adopt with changes, or reject, and every objection has a reply.
