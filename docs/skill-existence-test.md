# Skill existence test

Keep a skill only when it owns a distinct intent, trigger, procedure, output, and demonstrated
failure prevention. Otherwise it is branded prompt bloat. Strong generic alternatives disqualify
familiar work unless the skill adds a unique contract.

| Skill | Failure prevented |
| --- | --- |
| `ask-user` | agents guess or ask bare questions |
| `bulletproof` | load-bearing claims escape active verification |
| `debloat` | prose wastes context through repetition |
| `demolition` | advocacy masquerades as evidence |
| `dissect` | change proceeds from a partial code-path story |
| `drill` | mixing levels, implementing before place is locked, asking a lower question while a higher lock is open, or writing a plan instead of the next seam |
| `panel` | consequential alternatives collapse into one unchallenged recommendation |
| `promote` | transient content enters permanence unsanitized or broken |
| `remember` | verified lessons vanish or create a parallel memory store |
| `revolver` | broad work receives one narrow review frame |
| `settle` | solvable technical ambiguity reaches the user or becomes an arbitrary choice |
| `triple-check` | narrow high-risk work receives shallow or correlated review |

Reconsider a skill when real work shows overlap, native replacement, or loss of its distinct failure.
